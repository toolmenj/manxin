# 多人上線審查（2026-10-21）

三個只讀審查 agent（併發與資料一致性、安全與權限隔離、架構與擴充性）的結果，合併去重後依嚴重度排序。「已驗證」＝用腳本或對本機 API 重現過；「推測」＝讀程式碼判斷。重現腳本在當次 session 的 scratchpad（review-concurrency／review-security／review-arch）。

**守得住的部分（已驗證）**：使用者之間互相讀改信件、附件全部 404；同時按兩次寄出、出門與寫字同時、收件人兩分頁同時開信／撕信、同 seq 同時送都正確擋下；兩個 API 程序同時跑排程沒有重複（SKIP LOCKED）；前端 innerHTML 插入點都有跳脫，沒有寄件人攻擊收件人的存放型 XSS。真 PostgreSQL 16（embedded-postgres）跑 API 測試 62/67，5 個失敗是 `fonts-templates.test.ts` 在檔案中間二次 `makeApp` 清表造成的測試寫法問題。

## 低

- 信封文字、摺信沒有 seq／冪等，連點會寫兩次或多摺一次（`counter.ts:312-331`）。
- 單號先查再插，同時撞號回 500（`shipments.ts:63-66`）；23505 統一對應 409。
- 認領排程與時間軸用應用程式時鐘而非 DB `now()`；「已寄提醒」由時間推算而非寄信紀錄。
- SEQ_CONFLICT 後重新讀取失敗會原地高頻重打（`sheetWriter.ts:140-147`）。
- 狀態變更 POST 接受 `text/plain`（表單可送），沒有 Origin 檢查；沒有 helmet 安全標頭（點擊劫持）。
- 寄件人 `fromEmail` 未驗證，可讓提醒、退信寄給無關的人；寄件人姓名原樣放進通知信。
- 寄件人「拿出來」的附件收件人仍讀得到（`receive.ts:286-293` 沒檢查 `takenOutAt`）。
- 信紙字型欄位伺服器接受任意字串，只靠前端白名單（`desk.ts:37`、`art.ts:130`）。
- 沒有「登出所有裝置」。
- `/health` 不檢查 DB；關閉時不等正在跑的排程；資料表（jobs、tokens、sessions、outbox）無清理。
- 字型上傳整份讀進記憶體、交易失敗留孤兒檔。
- 時間規則漏到前端：`Tomb.tsx:76` 自算 30 天、`Track.tsx:256` 比對事件文字。
- 郵局路程頁每一幀 setState（`Post.tsx:80-94`）。
- DB 連線沒有 ssl、pool 大小固定、無 statement／idle timeout。
- 測試全在 PGlite（單一連線、交易互斥），看不出任何併發問題；沒有併發測試。
